M9 sprint 4: the indicators and KPI sets can be read as RDF that follows RIMO 0.2.0, in Turtle and in JSON-LD. `GET /api/v1/kpi/rimo.ttl` and `GET /api/v1/kpi/rimo.jsonld` need a token with the scope `kpi.framework.v1.read` (the role `user` holds it) and are never cached by a shared cache. `GET /public/kpi/rimo.ttl` and `GET /public/kpi/rimo.jsonld` (on the internal surface, like the public service reads) need no token and give the same definitions with `Cache-Control: public, max-age=300` and an ETag (a client that sends `If-None-Match` gets 304). Neither pair says anything about a service, a person or a measurement, and none takes a query parameter. Each indicator is a `rimo:KPI` with its name, description, example, a value node with the unit, its means of measurement and automation tools, and its relation (`rimo:mandatoryFor`, `rimo:recommendedFor` or `rimo:appliedTo`) to the KPI set, which is a RIMO service category (the RIMO one when the set is mapped to it, otherwise one minted for it). Set the setting `iriBase` of `kpi.framework` before you share an identifier: the identifiers name things and are not web addresses. The public API v1 gains two routes and no other change (additions only); a profile without `kpi.framework` has none of the four routes. The images do not contain a new runtime dependency.
