The `full` profile has a Data Submission page, `/submit` ("Data Submission" in the Main section of the navigation, "Datenmeldung" in German). A person reports the values of a service for a month in a form (the indicators grouped as Mandatory, Recommended and Optional with the words of your vocabularies, an input per value type with its unit and bounds, the stored values filled in, a save that stays disabled until every mandatory indicator has a value) or from a CSV, TSV or XLSX file: the page shows the first rows, proposes which column holds which indicator and lets the person change it, says what each value would do (new, changed, unchanged, rejected) with the reason in words, and records nothing while any value is rejected. The import template can be downloaded per service. A history lists the last runs and which of the last twelve months have every mandatory value. Who sees what: an administrator can report for every service, an approved member of an organisation for the services it runs; a person with no such service sees a page that says so. The page opens on a service and a month from the address (`/submit?service=<id>&period=YYYY-MM`). Texts are in English and German. New internal route `GET /kpi/ingestion/services` (the services the caller may submit for; not part of the public `/api/v1`), and the value types answered by `GET /kpi/value-types` now say how a form asks for a value (`input`, additive). The public API is unchanged; no setting, migration or runtime dependency is added.
