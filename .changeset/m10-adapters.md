Measurements can now be checked and recorded from a file or a form, and an import template can be downloaded per service. The `full` profile gains these internal routes (the signed-in pages use them; they are not part of the public `/api/v1`, which is unchanged): `POST /kpi/ingestion/preview` and `POST /kpi/ingestion/runs` (a CSV, TSV or XLSX file up to 2 MiB as `multipart/form-data`, or the values of a form as JSON), `GET /kpi/ingestion/runs` and `/runs/{id}` (the last 50 runs of a service), `GET /kpi/ingestion/adapters` and `GET /kpi/ingestion/template?service=&format=csv|xlsx`. A person may use them for a service when they may submit measurements for it (an administrator, or an approved member of its provider). A dry run (`dryRun: true`) says what each value would do and writes nothing; a commit that finds any bad row is refused as a whole (422 naming each row and column) and recorded as a run. A file is read in memory and never stored; an XLSX is checked against zip bombs, encryption and oversize before it is read (at most 20 MiB unpacked), formulas are read as their saved value and never evaluated, and the import templates escape cells that a spreadsheet would run as a formula. A new permission, `kpi.ingestion.measurement.ingest`, is held by the role `user` (a token that is to preview or record needs it). The image of the `full` profile grows by about 9 MB (the XLSX libraries); no setting or migration is added. `upsertBatch` now accepts up to 25 000 values per batch (it was 5 000).
