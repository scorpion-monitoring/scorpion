M7 sprint 5: the create wizard. A new page `/services/new` (reached from the "New service" button of the catalogue, for every person who may create a service) walks through three steps: **basics** (short name, name, a licence searched in the SPDX list and chosen with "OSI approved" and "deprecated" shown in words, stage, description, web address, further links), **who runs it** (the organisation that operates the service and the groups it belongs to) and **contact** (a role address and its kind, both or neither). A person who is not an administrator is offered only the organisations they are an approved member of; the server checks the choice again (403 for an organisation they are not a member of, 422 for an unknown one) and creates the service, its links and its field values in one transaction, with one request. Each step is checked in the browser before the person goes on, against the same rules the server applies; if the server still refuses something (a short name that is taken, a licence it does not list) the error is shown on its field, the wizard goes back to the first step that has one, and nothing the person typed is lost. A reload or a link asks first. The icon is uploaded on the screen after the creation, because the stored file refers to the service; that screen then links back to the services. New API route `GET /api/internal/services/schema` (permission `registry.services.service.create`, which every user holds): the steps and fields of the wizard with their widgets and message keys, one JSON Schema per step, the limits (at most 20 `sameAs` links, the lengths of the fields, the request size), the organisation roles, the defaults of a new service and `devConsole`; it holds nothing of any person or service. **The JSON console** (a text area that shows the form as JSON and takes edits back, checked like any other edit) exists only on a server that does not run in production: it is part of the answer of the schema route (`devConsole: true` when `NODE_ENV` is not `production`) and the page does not draw it otherwise, so a production instance has no console. Another module can add a step to the wizard by contributing to the registry `service.wizardStep`, with its own field type (and, for the browser, the control that draws it); its values are stored with the service's other values and a failure in it takes the whole creation back, leaving no service, link, value or event. The labels of the organisation fields read "Operated by" and "Part of" in English and "Betrieben von" and "Gehört zu" in German, and every text of the wizard exists in both languages. Operators: no setting changes; the web address of a service in a form is a single line.
