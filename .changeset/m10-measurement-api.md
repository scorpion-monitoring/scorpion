Adds the measurements to the public API and to the signed-in reads, in the `full` profile. `GET /api/v1/measurements?service=&indicators=&start=&stop=` returns the values reported for one service (`service` is required: its id or abbreviation) in the legacy envelope under `result`, in a stable order across pages (month, indicator name, id) with `pageSize` at most 100; each row keeps the legacy `kpi`, `value` and `date` and adds `id`, `indicatorId`, `iri`, `service`, `period` and `valueNumber`. `POST /api/v1/measurements?service=` records up to 500 values as `[{ kpi, value, date }]` (a KPI by name without case or by id, a month as `YYYY-MM` or a date): a month that already has a value is updated, never duplicated, the batch is all or nothing and a 422 names every bad item (`[3].kpi`, `[3].value`, `[3].date`). It answers `{ inserted, updated, unchanged }`. **A token now needs two scopes to write**, `kpi.ingestion.v1.write` and `kpi.ingestion.measurement.submit`, and its owner must be an Admin or an approved member of the service's provider: any other token is refused with 403, which closes the legacy gap where any key could write to any service. A client of the old application that read `data` or relied on a default page size of 1 000 has to change. The role `user` holds `kpi.ingestion.v1.read`, `kpi.ingestion.v1.write` and `kpi.ingestion.measurement.read` by default; administrators who changed the role may need to grant them. A preflight now names the methods of the path asked about (`GET, POST, OPTIONS` for `/api/v1/measurements`, `GET, OPTIONS` for the others). The OpenAPI document gains the two routes and nothing else.
