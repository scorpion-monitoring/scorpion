The inbox, the dashboard and the live count (M5, fourth part, second half). The header has a **bell** with the number of unread inbox items, a menu with the latest ones ("Mark read", "Mark all read") and a full **Inbox** page; the number is live. People can choose which messages reach them by mail and in the inbox on the new page **Notification settings** (`/profile/notifications`; security messages are shown locked). The start page of a signed-in person is a **dashboard**: administrators and reviewers see cards (registrations waiting for approval; mail that could not be delivered), other people see none.

New API: `GET /inbox/stream`, a server-sent event stream (`text/event-stream`) of the caller's own unread count (permission `core.notifications.inbox.read`; session cookie or an access token with that scope). It sends only `event: unread` with `{"count": n}` and a heartbeat comment every 25 s, never the content of an item, and no event ids (a reconnect starts with the current count). It ends within one heartbeat when the session or token stops being good (logout, ended or expired session, revoked token, lost permission). **Operators:** the web proxy passes it unbuffered and exempts it from `API_TIMEOUT_MS`; a reverse proxy in front of the instance must not buffer it or cut it before about 30 s of silence, or the page falls back to asking once a minute. New settings of `core.notifications`: `inboxStream.perUser` (3) and `inboxStream.global` (200) cap the open streams (429 with `Retry-After`). It uses one more channel (`notify_inbox`) on the Postgres connection that delivery already holds; no new connection.

Changed behaviour: three identity mails now also create an inbox item: the registration request (administrators), the approval of an account, and the notice that somebody tried to register with your address. Mails whose link is a credential (reset, verification, provider link) never do. For module authors: widgets (`ui.widget` entries and an exported `widgets` in the `ui` entry), and `recheckActor` in the request pipeline, with a `passive` flag for the authenticator, for any response that outlives its request. ADR-0028 records the design. No new runtime dependency.
