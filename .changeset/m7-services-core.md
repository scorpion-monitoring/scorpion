M7 sprint 1: the `registry.services` module, in the `registry` and `full` profiles. It adds the service record (slug, name, licence, stage, description, URL, `sameAs` links, a contact point, a provider and any consortia) with five new tables (`svc_service`, `svc_service_organisation`, `svc_field_value`, `svc_slug_history`, `svc_license_cache`, created by a migration at start) and these internal API routes: `GET /api/internal/services`, `/services/{id}`, `/services/by-slug/{slug}` (an old slug answers the current record with `redirectedFrom`), `POST /services` (administrators only in this release; one transaction for the service and its organisations; an unknown organisation, stage or licence is a 422 and a taken slug a 409), `GET /licenses` (the SPDX list for the licence field) and `GET /service-roles`. Every signed-in person can read services; the contact point is shown to administrators and, while the new setting `exposeContactPoint` (default on) is on, to other signed-in people, and is never in a list. The setting `allowPublic` (default on) is declared now and takes effect when public services arrive in a later release; nothing is public yet. An organisation that a service uses can no longer be deleted or change its type, and a stage that a service has can no longer be deleted (only deactivated). The wizard and the metadata schema are typed configuration files that the server validates when it starts: a wrong field type, column, step or order stops the start with a message that names the file and the field, and another module's contribution that is wrong stops it with a message that names that module. The licence list comes from SPDX, is cached in the database for a day and falls back to a copy that ships with the image when the network is down. The audit trail records `registry.service.created@1` when `core.audit` is in the profile.
