Operators can migrate from the legacy application (`ipk-bit/scorpion`). `pnpm migrate-legacy compare <snapshot> --mapping <file> --report <dir>` reads every migrated value back and checks it against the snapshot, per service, KPI and month, and checks the other migrated records (organisations, services, KPI sets and each service's KPIs, users and their claims, memberships). It writes nothing to the database. Each difference is expected (a rule of the migration explains it, such as a month written as 0 or a point in a future month), reported (a value or record a person may have changed after the run), or unexplained; the command exits with code 1 when any difference is unexplained. The report is private (mode 0600, outside the repository). The tool's README now has the runbook of the migration and the cutover: preparing the new instance, fetch, plan, dry run, run, compare, a second run, the announcement mail, granting Admin to legacy administrators, and deleting the files afterwards. For module authors, `kpi.ingestion` adds the trusted read `reads.storedValuesAsSystem` (every value of a service with the source that wrote it; no route).
