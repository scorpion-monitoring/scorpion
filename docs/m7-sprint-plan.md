# M7 Sprint Plan: `registry.services`

Status: decided, 2026-10-12. The maintainer answered the open questions of the draft (§14, Decisions 1 to 10); the points that the plan settles itself, in the maintainer's direction, are Decisions 11 to 20 in §14 and are marked "proposed" until the maintainer says otherwise. No question is open.
Scope source: [implementation.md](implementation.md) §4, M7, plus the maintainer's addition of 2026-10-12: **a service presents a Schema.org `Service` profile, as an organisation presents an `Organization` profile** ([ADR-0033](adr/0033-organisation-model.md), [m6-sprint-plan.md](m6-sprint-plan.md) §3). Closes defect 2 and the service part of defect 14 of FEATURES §5; it builds on defect 1 (every route has a permission and an ownership check). Releases as `0.9.0` (`0.8.0` is M6, released 2026-10-12). Gate 2 follows M8.

M7 is size L in `implementation.md`. The Schema.org profile, the public reads that the Reviewer controls and the two edit groups add about a sprint to the original scope, so the plan has **six sprints (about 6 weeks for one developer)**. It is the second module that uses a resource policy (`service.member`, built on the M6 pattern of ADR-0034, with **no change in an ASVS-scoped path**), the first with **anonymous reads of per-resource data** (a flag that only Reviewers and Admin set), and the first that other modules extend through several registries (`service.fieldType`, `service.wizardStep`, `service.orgRole`, `service.facet`, `service.profileContributor`).

## 2. Cross-sprint rules

- Stay inside M7. Anything else goes to `docs/backlog.md` (§12). KPI sets and categories (M9), measurements (M10), the public API v1 (M8), onboarding (M15) and publications (M16) are not here.
- **One pull request per sprint** (CLAUDE.md "Working style"). ADRs, READMEs, backlog lines, the generated route table and review fixes go into the sprint's pull request. Push and open it when the sprint is complete and verified locally: `pnpm check`, `pnpm test --filter @scorpion/registry-services` and the packages touched, the full `pnpm test` and a full `CI=true pnpm test:e2e` before the last sprint, `pnpm security:asvs` after a sprint that changes `docs/security/**`. If a sprint passes about 1500 changed lines of non-test code, split it into stacked pull requests as CLAUDE.md allows.
- **Module rules** (CLAUDE.md): one package `modules/registry-services` with `module.ts` and `public.ts`; dependencies only in `package.json` (`core.authz`, `core.settings`, `core.identity`, `core.blob`, `core.notifications`, `registry.organisations` as dependencies; `core.ui-shell` and `core.audit` as optional peers; `@scorpion/integrations` for SPDX); layers `ui/` → `routes` → `service/` → `db/`; tables carry the prefix `svc_` (`tablePrefix: 'svc_'`, Decision 11); foreign keys point only to the module's own tables. **No foreign key to `org_organisation`, to `identity_user` or to the blob table**: organisation ids, user ids and the icon's blob id are plain columns checked in the service, as in M6.
- **No hard-coded lists.** The stages come from the `stage` vocabulary; the roles an organisation can play on a service (`provider`, `consortium`) are the registry `service.orgRole`; field types, wizard steps, facets and profile properties are registries; limits (`sameAs` at most 20, field lengths) are named constants with a test; every label comes from the message catalogue, a registry entry or the vocabulary term. A test fails on a pg enum and on the words `provider` or `consortium` in a message of a screen.
- **No hard-coded branding** (CLAUDE.md rule 9): the JSON-LD takes the origin, instance name and addresses from settings and the request. The contact point is the service's role address, never a user's and never the recipient of a mail.
- **Three editor groups on one record** (Decision 5, §3 of ADR-0036). One `update` method and one icon path; the field-rules table `service/field-rules.ts` says which access a set of fields needs, so each group adds a policy answer and a permission, never a second code path or a copy of the validation. A request that touches a field its caller may not write is refused **whole** (403), never partly applied.
- **Layer rule 5:** the service layer is the only way to change data (routes, the wizard, M8 reads, jobs and, later, the migration tool). Every multi-row write runs in `ctx.db.tx()` and emits its event inside it. Creating a service with its organisation links and field values is **one transaction** (the legacy app was not transactional, FEATURES §3.5).
- **A service method needs:** an integration test against real Postgres (Testcontainers), a denied-permission case per scoped permission, a rollback case for a multi-row write, and a concurrency case where two writers can meet (two renames to one slug, a rename racing a create, two publications).
- **Pure logic gets table-driven unit tests:** slug rules and the history lookup, the field-rules table (`requiredAccess`), the Schema.org builder and its escaping, the catalogue query builder (filters, facets over the filtered set, sort, page maths), the SPDX normalisation, the config validator, the `sameAs` and contact validation shared with organisations.
- **Routes** use `createRoute()` with a `permission` or `public: true` **with a reason**; every list uses the legacy envelope with 0-based pages and a stable sort (key, then id); invalid input and unknown references are 422 or 404, never 500 (defect 14). Each new route gets a row in the matrix of `defect-01.privilege-escalation.test.ts`, a regenerated route table in `docs/security/authorization.md`, and is read by `response-fields.test.ts`. Public routes are rate limited (the `default` group) and named in the route table with their reason.
- **Security rules** (CLAUDE.md): permissions are checked twice (route and service); **a non-public service is 404 on every public route and page**, never 403; the public profile **never carries the contact point** and a public page shows no member, no stage-independent private field and no edit control; no `{@html}` outside the one audited JSON-LD component (Decision 15 moves that file, not the rule); uploaded icons go through the blob store; no secret, address or token in an event, log or audit payload.
- **Scoped paths.** M7 plans **no change** to `modules/core-identity/**`, `modules/core-authz/**`, `apps/server/src/pipeline/**` or `packages/contracts/src/route.ts`. If a prototype or a test shows that one is needed, the plan stops and asks. M7 does change `docs/security/**` (field tables, route table, V8 evidence): each sprint says whether it updates the chapter YAML and carries the label (rule of §0 item 4).
- **A module with events** is added as an optional peer of `core.audit` and gets entries in `decisions.ts` in the same sprint; `decisions.test.ts` fails otherwise.
- Use the factories in `packages/testing`; add `makeService` (with organisations, field values, an icon, `public`) there. Never hand-write fixture SQL.
- Update the module README in the same commit as every manifest change. A test never calls a third party (SPDX is stubbed; the bundled list is the fallback). No new runtime dependency is expected; if one appears, the pull request description names it and says why.
- Every pull request carries a changeset (package `scorpion`), written for operators and API users. Sprints 1 to 5 are `minor`; the release turns them into `0.9.0`.

## 3. Mapping of the service to schema.org

A service serves a [Schema.org `Service`](https://schema.org/Service) profile (Decision 3). One pure function, `toSchemaOrg(service, { origin, basePath, organisations, contributors })`, builds it; the signed-in route, the public route and the page block all use it, never a second mapping. The type is fixed (`Service`); the builder takes it as an argument, so a later `service.type` registry needs no new builder.

| Stored field                        | schema.org property                                         | Notes                                                                                                                                                                                   |
| ----------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| (fixed)                             | `@type`: `Service`                                          |                                                                                                                                                                                         |
| `id`                                | `@id`                                                       | the absolute URL `{origin}{basePath}/services/{id}`; **stable across a slug rename** (the page resolves an id and redirects to the current slug)                                        |
| `name`                              | `name`                                                      |                                                                                                                                                                                         |
| `slug`                              | `alternateName`                                             | the abbreviation, as for organisations                                                                                                                                                  |
| `description` (plain text)          | `description`                                               | plain text, never HTML                                                                                                                                                                  |
| `url`                               | `url`                                                       | the service's own address                                                                                                                                                               |
| `same_as` (list of URLs)            | `sameAs`                                                    | `http(s)` URLs only                                                                                                                                                                     |
| `icon` (blob id and hash)           | `logo`                                                      | an `ImageObject` with `url` = origin + base path + `/api/internal/files/{hash}`                                                                                                         |
| `license` (SPDX id)                 | `license`                                                   | `https://spdx.org/licenses/{id}.html`; omitted for an id the bundled list does not know                                                                                                 |
| provider (role `provider`)          | `provider`                                                  | an organisation node `{ @type, @id, name, url }` built from `toSchemaOrgAsSystem(id, { includeContact: false })`; the organisation's own profile carries the rest                       |
| consortia (role `consortium`)       | `brand`                                                     | organisation nodes as above; the network the service is offered under (Decision 7). Omitted when there are none                                                                         |
| category (M9)                       | `serviceType` and `category`                                | **contributed by `kpi.framework` through `service.profileContributor`**; M7 builds the registry and tests it with a fixture. The provider chooses the category in the wizard from M9 on |
| a configured field with `schemaOrg` | one of `termsOfService`, `areaServed`, `audience`, `slogan` | a field of the config may name one of these four properties; no field shipped in M7 uses it (a fixture config does), so a deployment can add them without code                          |
| `stage`, contact point              | **not mapped**                                              | schema.org has no lifecycle property, and `Service` has no `contactPoint` (Decision 6). Both are stored, shown on the page to those who may see them, and never in the JSON-LD          |
| (not stored)                        | `offers`, `availableChannel`, `hoursAvailable`              | not built; out of scope (§12)                                                                                                                                                           |

A property with no value is **omitted**, never `null` or an empty string. The output is escaped by the same `serializeJsonLd` as the organisation's. A contributed property is accepted only if its name is on an allow-list kept in code (`serviceType`, `category`, `audience`, `areaServed`, `termsOfService`, `slogan`, `serviceOutput`) and its value is a string, a URL or a list of them; a contributor cannot overwrite `@id`, `@type`, `name`, `provider` or `license`.

## 5. Sprint 1: the module and the service record

**Branch:** `feature/m7-services-core`. **Goal:** an administrator can create and list services through the API (a service with one provider, any consortia, a licence, a stage and an icon-less record), another module can contribute a field type, a wizard step, an organisation role and a facet, a bad configuration stops the server at startup, and the `registry` profile carries the module.

Work items

1. **ADR-0035 and the lines of §13 in `implementation.md`** (first commit). ADR-0035 records the tables, the slug rules, the config files, the registries and their entry shapes, the mapping of §3 and the contributor registry, and why the catalogue is a query function (defect 2). It also records that **`svelte-keyed` and the ISA Wizard questionnaire were evaluated and not adopted** (Decision 21): the form state is one nested object addressed by JSON pointers, the step and field format keeps the legacy shape (`title`, `texts`, `fields`, `component`) with typed, validated config, and a later **base path per step** (the same field list bound below a nested path, so M9 or M15 can reuse a step) is noted as an option, not built.
2. **Create `modules/registry-services`:** `module.ts` (id `registry.services`, `tablePrefix: 'svc_'`), `public.ts`, `README.md`, `package.json` (`@scorpion/registry-services`, exports `./module`, `./public`, `./ui`), `db/schema.ts`, `migrations/`, `routes.ts`, `service/`, `settings-schema.ts`, `config/` (item 5). Run `pnpm modules:sync`. Copy the shape of `registry-organisations`.
3. **Tables** (`pnpm db:generate --filter @scorpion/registry-services`):
   - `svc_service`: `id` (UUIDv7), `slug` (case-insensitive unique), `name`, `license` (nullable SPDX id), `stage` (a term id of the `stage` vocabulary, not an enum), `description`, `url`, `same_as` (`text[]`), `contact_email`, `contact_type`, `icon_blob_id`, `icon_hash`, `public` (boolean, default false), `published_at`, `published_by`, `created_at`, `created_by`, `updated_at`, `updated_by`. Check constraints: the contact pair is set together or not at all, `published_*` are set together with `public`.
   - `svc_service_organisation`: `service_id` (cascade), `organisation_id` (plain column), `role` (a key of `service.orgRole`, checked in the service), unique on `(service_id, organisation_id, role)`.
   - `svc_field_value`: `service_id` (cascade), `field_key`, `value` (`jsonb`), unique on `(service_id, field_key)`: the values of configured fields that are not columns.
   - `svc_slug_history`: `slug` (case-insensitive unique **across the current and the old slugs**: an old slug is never reused by another service), `service_id` (cascade).
   - `svc_license_cache`: one row, the fetched SPDX list and its time (item 7).
   - A test fails on a pg enum and on a table without the prefix.
4. **The registries** (declared by this module; entries are Zod-checked by the loader, which names the contributing module in the message, as for `org.type`):
   1. `service.orgRole`: `{ id, labels, orgTypes: string[], min, max, order }`. The module contributes `provider` (`orgTypes: ['provider']`, exactly one: `min: 1`, `max: 1`) and `consortium` (`['consortium']`, `min: 0`, `max: 20`). The service refuses an organisation whose `org.type` is not in `orgTypes`, an unknown organisation (**422**, defect 14) and a count outside `min` and `max`.
   2. `service.fieldType`: `{ id, labels, schema(config) → Zod, jsonSchema(config), widget, toValue?, schemaOrg? }`. Seeded: `text`, `select`, `multi-select`, `license`, `organisation` (the caller's own providers, or consortia for a role), `image`. `kpi-set` and any other type arrive from other modules.
   3. `service.wizardStep`: `{ id, order, labels, fields?, component?, applies? }`. The module's own steps come from its config file (item 5); another module contributes more (M9: the category).
   4. `service.facet`: `{ id, labels, order, values(filters) → counts }` (sprint 4 uses it). Seeded: `consortium`, `stage`, `license`, `provider`; M9 adds `category`.
   5. `service.profileContributor`: `{ id, contribute(service, ctx) → properties }` (§3, the allow-list is enforced when the profile is built and tested with a fixture).
   6. The module contributes `org.usage` (`service_organisation` counts the rows of an organisation) and the `usage` entry of the `stage` vocabulary (a service uses its stage; `validateTerm` on save).
5. **The two config files** (`config/steps.ts`, `config/fields.ts`; typed TypeScript, the successor of `steps.json` and `service_schema.json`). They list the steps (id, title key, an optional list of `intro` message keys for the paragraphs the legacy `steps.json` called `texts`, `fields` or a `component`) and the fields (a JSON pointer `path` into the one nested form object, for example `/name` or `/contact/type`; type, label key, help key, `required`; `storage`: a column of `svc_service` or a key of `svc_field_value`; optional `schemaOrg`). The shipped steps are **basics** (slug, name, licence, stage, icon, description, URL, `sameAs`), **provision** (provider, consortia) and **contact** (the contact point). The validator runs when the module starts and **refuses to start** with a message that names the file and the field for: an unknown field type, two fields with one key, a column that does not exist, a step that names an unknown field, a `schemaOrg` outside the allow-list, a step order clash. A fixture config proves each failure and a fixture with a configured extra field proves `svc_field_value`.
6. **Field validation** (pure, `service/fields.ts`, table-driven tests): slug `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` and **not shaped like a UUID** (so `/services/{id}` and `/services/{slug}` cannot clash; the same rule rejects the slugs `new` and the other reserved words of the page routes); `name` 1 to 200; `description` up to 4000; `url` and `sameAs` as for organisations (the shared normaliser moves to `@scorpion/kernel` or stays a copy with a test that keeps the two equal; Decision 18); contact pair as for organisations; stage a term of the vocabulary; licence an SPDX id (item 7).
7. **SPDX adapter** (`packages/integrations/src/spdx.ts`): `createSpdx({ fetch, cache, now })` with a 5 s timeout, retry with backoff, a cache port (the module supplies it over `svc_license_cache`, 24 h) and a bundled fallback copy of the list (a generated file with its version; a test fails when it is older than the pinned release). `search(q, { limit })` returns `{ id, name, osiApproved, deprecated }`; `has(id)` is true for current and deprecated ids; a stub for tests and `NODE_ENV=test` that never touches the network. The README of the package gets the SPDX section. An unknown licence id is **422**; a deprecated one is accepted and marked deprecated.
8. **Service layer** (`service/services.ts`, every method takes the `actor`): `create` (one transaction: the service row, the organisation links, the field values, the event), `get`, `getBySlug` (an old slug answers the current record with `redirectedFrom`), `list` (a plain list with `q`, sort and pages in this sprint; the facets come in sprint 4) and the trusted reads for M8 and M9 on `public.ts` (`findByIdsAsSystem`, `findBySlugAsSystem`, `listByOrganisationAsSystem`, `existsAsSystem`; none checks a permission, the `AsSystem` suffix says so). `update` comes in sprint 2. Sprint 1 permits creating to the plain `registry.services.service.manage` (Admin) and reading to `…service.read`; the member rules arrive in sprint 2.
9. **Routes** (`createRoute()`, internal surface): `GET /services` (`…service.read`; `q`, `page`, `pageSize`), `GET /services/by-slug/{slug}`, `GET /services/{id}`, `POST /services` (`manage`, `audit: true`, 201), `GET /licenses?q=` (`…service.read`; the SPDX search for the wizard) and `GET /service-roles` (the `service.orgRole` entries, for the form). The role User and Reviewer get `…service.read` through `authz.defaultRole`.
10. **Events and audit.** `registry.service.created@1` (`{ serviceId, by, actorId }`; ids and field names only). The module is added as an optional peer of `core.audit` and `decisions.ts` gets the entry (logged, not critical). The README of `core.audit` lists it.
11. **The `registry` and `full` profiles** list `registry.services`; `profiles.test.ts`, the image legs and the module-set check are updated (the CI matrix names profiles, not modules, so nothing else changes). `pnpm scorpion profile:generate registry` and `full` leave no diff. ## 14. Decisions taken

**The maintainer, 2026-10-12** (answers to the questions of the draft):

1. **The service category comes from `kpi.framework` through a registry (extension point), not from M7.** The profile gets `serviceType` and `category` from it. _Reason:_ the approved architecture keeps `registry.services` independent of `kpi.framework`; "it is necessary that the provider can decide on the service category in the wizard as soon as M9 becomes available". _Changed:_ the registries of sprint 1, the wizard of sprint 5 (the contributed step and its fixture), §3, the hand-off table.
2. **Fixed schema.org type `Service`.** Not a type registry. _Reason:_ services already have a category that plays the part of a service type (Decision 1). _Changed:_ §3, §12.
3. **A service presents a Schema.org `Service` profile**, like an organisation presents an `Organization` profile. _Changed:_ §3, sprint 3, sprint 6, §13.
4. **Public access is decided per service by Reviewers and Admin; initially every service is private (signed-in only).** _Reason:_ the profile is only useful to crawlers when public, but exposure is an editorial choice. _Changed:_ the flag, the permission, the public routes and pages, the setting `service.allowPublic` (Decision 16), sprints 2, 3 and 6, the acceptance rows.
5. **Two edit groups for members and managers, and consortia editable by members.** The identity of a service is its **slug and its provider** (managers of the provider and Admin); everything else, name, stage, licence and the consortia included, is edited by any approved member. Reviewers and Admin publish. _Changed:_ the permissions, the field-rules table, the screens.
6. **The contact point is stored and shown on the page (to those the table names), but is not in the profile**, because `Service` has no such property. _Changed:_ §3, sprint 2 item 8, the public records.
7. **Consortia map to `brand`**, the owning organisation to `provider`. _Changed:_ §3.
8. **A public organisation profile exists only for organisations with at least one public service** (the provider or a consortium of one). Refines Decision 15 of M6. _Changed:_ sprint 3, the hand-off table, the acceptance rows.
9. **New fields: `description`, `url`, `sameAs`, a contact point.** (The maintainer's answer to "which new fields"; the icon, licence and stage are the legacy fields.) _Changed:_ the tables and the schema.org mapping.
10. **The wizard and the schema are a build-time configuration** (typed config files validated at startup; other modules extend through registries). _Reason:_ as CLAUDE.md for plugins: a change means a rebuild. _Changed:_ sprint 1 item 5, sprint 5.

**The plan settles these itself, in that direction; they are proposed and change nothing outside M7 if the maintainer disagrees:**

11. **Table prefix `svc_`** (short, as `org_` in M6).
12. **No `scoped` route flag and no pipeline change:** a plain permission on the route and the scoped check in the service, as ADR-0034 and M6 did. The backlog entry says to build the flag only if `service.edit` cannot use that pattern; the plan finds that it can.
13. **Facet counts over the set filtered by all other facets and the search** (the standard faceted behaviour; FEATURES asks for "the filtered set"). A value with no service in the set shows only when selected.
14. **Creating needs membership of the chosen provider**, not management: setting the slug and the provider at creation is not a change of an existing identity. Renaming and moving later need a manager.
15. **The one audited `{@html}` component moves to `packages/ui-kit`** so both modules use it; the exception stays one file (§7 item 5).
16. **`service.allowPublic` (default on)** lets an operator switch every anonymous read off; with it off the public routes and pages answer 404 and the publish action is refused.
17. **Public routes are internal-surface routes** under `/public/…` with `public: true`, a reason and a one-minute cache; the `/api/v1` aliases are M8's. A non-public record is a **404 with the body of an unknown id**, never a 403.
18. **Shared code is shared by moving it to ui-kit or the kernel, not by importing another module's UI:** `ImageBlock` (from `LogoBlock`), the URL and `sameAs` normaliser, and, if the duplication is large, the generic form; the module boundary rule stays.
19. **The `@id` of a service is its id URL**, stable across renames; the slug is `alternateName`. Slugs may not look like a UUID or a reserved page word, and an old slug is never reused.
20. **No service delete in M7** (`TERM` ends a service's life; a delete needs a usage check from the KPI modules).
21. **The wizard keeps its state in one nested object addressed by JSON pointers; `svelte-keyed` and the ISA Wizard questionnaire are not adopted** (suggested by the maintainer, evaluated on 2026-10-12). _Reason:_ Svelte 5 deep state and `SchemaForm`'s pointers already bind a value to a path, the format of the ISA Wizard is the legacy `steps.json` shape that the plan already carries over, and a new runtime dependency needs a justification that is not there. Taken over: the `intro` paragraphs per step and the path-addressed fields. A **base path per step** is recorded in ADR-0035 as a later option. A silent skip of an unknown field type, a remount of the step on every move and an untyped config are the things not taken over. _Changed:_ sprint 1 items 1 and 5, sprint 5 item 1.
