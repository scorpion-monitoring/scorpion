## 2. Cross-sprint rules

- Stay inside M8. Anything else goes to `docs/backlog.md` (§8).
- **One pull request per sprint** (CLAUDE.md). ADRs, READMEs, backlog lines, the regenerated OpenAPI documents and review fixes go into the sprint's pull request; push when the sprint is complete and verified (`pnpm check`, the tests of every package touched, the full `pnpm test`, a full `CI=true pnpm test:e2e`, `pnpm security:asvs`, `profile:generate full --check`, `openapi:generate --check`).
- **A v1 route is declared once** with `createRoute()` in the module that owns the data and registered with `r.public('v1', …)`; it has a `permission` (a v1 route is never `public: true`: an anonymous read of v1 is not planned, Decision 2), a stable sort (key, then id), the legacy envelope `{ metadata: { currentPage, pageSize, totalCount, totalPages }, result: [...] }` with 0-based pages, and `audit: true`.
- **v1 changes are additive.** The spec of a released version is the contract; a field is never removed or renamed, a required request field is never added. The sprint-3 diff job enforces it; a breaking change goes to v2 with an ADR.
- **The service layer is the only way to read and change data.** A v1 handler calls one service method, as an internal handler does; `public-api` holds no query. A module's v1 read never returns what the module's internal read hides (the contact point of a service, the members of an organisation): the field tables of `docs/security/authorization.md` get a v1 column or section, and `response-fields.test.ts` walks the v1 schemas too.
- **Every list says how it sorts and pages** in its description, and the contract test proves an endpoint with `pageSize` larger than the total, a last page, an empty page and a stable order across pages (defect 15).
- **Input is Zod with size limits;** an unknown reference or a bad filter is 422 problem+json, never 500 (defect 14 applies to v1 as well).
- **No hard-coded branding.** The server URL in the spec and in `/docs` is the origin of the request plus the base path; the title and contact of the spec come from settings.
- **Scoped paths.** M8 changes `apps/server/src/pipeline/**` (the CORS step, sprint 1) and adds or changes `docs/security/**` (the v1 field tables, the route table). Each sprint says which chapter files it updates. It plans **no** change in `modules/core-identity/**`, `modules/core-authz/**` or `packages/contracts/src/route.ts`; if a prototype shows that one is needed, the plan stops and asks.
- Update a module's README with every manifest change. No new runtime dependency is expected (Decision 4); a development dependency for the spec diff (Decision 6) is named in the pull request description.
- Every pull request carries a changeset (package `scorpion`); sprints 1 and 2 are `minor` (an API users can call), sprint 3 `minor` or `patch`; the release turns them into the next version.

## 4. Sprint 1: the module, the spec, CORS and audit

**Goal:** the shell of the public API works with no data route: a token holder can call a (fixture) v1 route, a browser from an allowed origin can too, every call is audited, and the spec says what is there.

Work items

1. **Prototype** (§0 item 4) first; the answers go into ADR-0037.
2. **ADR-0037 (the public API):** one module, how the v1 routes are collected (the registrar already does it), the runtime spec, the CORS rule, the `api` audit channel, the permission model of a token (a v1 route's permission must be one the token's scopes name and its owner holds, ADR-0015), and the compatibility rule (additive only; the spec diff).
3. **The module** `modules/public-api` (`module.ts`, `public.ts`, README): serves `GET /api/v1/openapi.json` built at runtime from the v1 routes of the loaded modules (the same generator as `openapi-generate.ts`, so the committed document and the runtime one cannot differ; a test compares them for the full profile). The server URL is the request's origin plus the base path.
4. **CORS allow-list** (the pipeline step, ASVS-scoped): origins from a `core.settings` value of `public-api` (empty by default: same origin only). Only `/api/v1/*` answers a preflight; an origin not in the list gets no CORS header (the request itself is judged by the token as usual); `Access-Control-Allow-Origin` is the origin itself, never `*`, and never `Allow-Credentials` (a v1 call carries a token, not a cookie; a cookie session on `/api/v1` stays refused if it is today). A change to the list takes effect without a restart.
5. **The audit writer:** a v1 call (allowed, denied or rate limited) is one `api`-channel entry with the route template, status and the token's id (never the token), with the retention that exists. The first v1 route with `audit: true` proves the backlog item on `surface`.
6. **Per-token and per-address limits proved for v1** with a test, without changing a limit: a token is limited by its own bucket, so two tokens from one address do not share one and one token from two addresses does not escape (`pipeline/rate-limit.ts` already keys both; the test makes the claim on the v1 surface; **the prototype showed it was not true as written, see Decision 5 amended**).
7. **The contract-test harness** in `packages/testing`: given a v1 route, call it with a factory token and validate the response (status, body, headers, the envelope, the sort) against the route's own schema from the spec; a route without a contract test fails a walker (as `response-fields.test.ts` does for the internal API). Categories and indicators of M9 plug into it.
8. **Settings and messages:** the `public-api` settings (the allow-list, the spec's title and contact), their schema, README and the settings page text (en and de).

Tests: the module's integration tests against real Postgres (the settings value, the runtime spec equals the generated one), the pipeline tests for CORS (allowed, disallowed, preflight, no `*`, no credentials, a changed list), the audit entries (a denied call included), the per-token limit, the harness's own tests.

ASVS: V7 and V8 chapter files updated (CORS and the per-token limit as evidence, tagged tests); the other two chapters carry the `asvs-no-impact` line with a true reason. **If an existing requirement stops being true because of the CORS step, the entry says `fail` with the sprint-plan link, not `pass`.**

Definition of done: a fixture token calls a fixture v1 route from an allowed origin and is audited; `/api/v1/openapi.json` lists it; every check of §2 is green.

## 5. Sprint 2: providers and services

**Goal:** the two v1 reads of the legacy API, with the three defects of defect 15 fixed.

Work items

1. **`GET /api/v1/providers`** in `registry.organisations`: all providers or, with `is_member=true`, those the token's owner is an approved member of, and, with `is_member=false`, **the others** (both correct, tested against a brute-force count of generated data). Permission `registry.organisations.v1.read` (or the existing read permission, Decision 1). A parameter that is not a boolean is 422. The envelope, 0-based pages, sort by abbreviation then id, `totalCount` over the filtered set.
2. **`GET /api/v1/services`** in `registry.services`: filters `service` (abbreviations) and `provider` (abbreviations) as in the legacy API, plus the catalogue's own filters where they are cheap (stage, licence); **`consortia` filled** (the case that was always empty), one row per service whatever its number of consortia, a service with none shows `[]`; sort by abbreviation (slug), then id. It calls the catalogue query function; no new query.
3. **What a row carries** is pinned in the plan before code (a table in the sprint's pull request): the legacy fields (abbreviation, name, the provider, the consortia, the stage by its term key) and nothing the internal read hides; **the contact point never**; a service that is not public is returned to a holder who may read it internally, with its `public` flag. The field tables of `docs/security/authorization.md` get the v1 rows; the walker covers them.
4. **`GET /api/v1/services/{id}` and `GET /api/v1/services/{id}/schema-org`** (Decision 3): the same builder and escaping as the internal route, no contact point; contract tests like the other routes.
5. **Contract tests** for every route with the harness of sprint 1: the envelope, the stable order across pages, empty and last page, a bad filter (422), an unknown provider abbreviation (an empty list or 422, decided in the ADR addendum and tested), a token without the scope (403), no token (401), the `X-API-Key` alias.
6. **Regression tests for defect 15:** `defect-15.v1-reads.test.ts` (`is_member=false`, `consortia`, and the `totalCount` that counts the filtered set), never weakened.
7. **Docs of the routes:** each v1 route has a summary, a description of its sort and paging, and an example; the generated spec is regenerated and committed (`pnpm openapi:generate`); the module READMEs list the routes.

Tests: integration tests per service method (a denied case, the `is_member` matrix, a service with zero, one and two consortia), contract tests, the field-table walker, the regression test.

ASVS: V8 gets the v1 permission entries; V7 only if a token rule changes (it should not).

Definition of done: a token with the two scopes lists providers and services in the legacy shape with the three defects gone; the committed spec is the first version of the contract.

## 6. Sprint 3: the documentation (Scalar), the compatibility gate, the journey and Gate 2

**Goal:** a person finds the API, gets a token and makes a call from the documentation; CI protects what was published; Gate 2 can be judged.

**What the prototype of 2026-10-14 already showed** (a throwaway page in headless Chromium, nothing of it committed; sprint 3 repeats it in the real route as item 1):

- `@scalar/sveltekit` 0.3.29 is a **`+server.ts` handler** (`ScalarApiReference({ url, cdn, nonce, pageTitle, … })`) that answers a **complete HTML document**, not a Svelte component. The document has an inline `<script>` that configures Scalar and loads the bundle from a CDN. By default that is `cdn.jsdelivr.net/npm/@scalar/api-reference` **without a version** (always the latest). The `cdn` option takes another URL, so we serve a pinned copy ourselves. With a `nonce` (strict CSP) the wrapper uses the single-file bundle.
- The single-file bundle of `@scalar/api-reference` 1.74.0 (`dist/browser/standalone.js`, 4.5 MB, no lazy chunks, no `eval`) rendered the 5 routes of the committed v1 document from our own origin, with **no request to another origin** (`withDefaultFonts: false`) and **nothing in `localStorage`** (`persistAuth` is off by default). The strings `fonts.scalar.com`, `proxy.scalar.com`, `api.scalar.com`, `dashboard.scalar.com`, `client.scalar.com` and `web-pulse.io` are in the bundle: they are reached only through options we leave off, and `connect-src 'self'` would refuse them anyway.
- **CSP.** Scalar injects `<style>` elements and `style` attributes at run time. Under the shell's policy (`style-src 'self'` with nonces, no `unsafe-inline`) the page produced **19 violations**; with `style-src-attr 'unsafe-inline'` still 4; with `style-src 'unsafe-inline'` **none**. Scripts stay `'self'` plus the nonce. So the reference document needs `style-src 'unsafe-inline'`, and **only** that document (Decision 9).
- **The v1 document has no `securitySchemes`.** Scalar's authentication panel would offer nothing to paste a token into, and "Test Request" would answer 401. Item 3 adds them.
- **Tailwind.** Scalar's cascade layers meet Tailwind's only when both styles are in one document. The reference is its own document, so the heads-up of the Scalar documentation (declare `@layer scalar-base, scalar-theme, scalar-config, theme, base, components, utilities;` before `@import "tailwindcss"`) does not apply now; it is recorded in ADR-0038 for the day Scalar is embedded in a shell page.
- The committed document of the last tag (`v0.9.0`) has no paths, so the first spec diff compares against an empty API.

Work items

1. **Prototype in the real route first** (stop and say so if it fails): the route of item 5 with the final headers, called in Chromium under both base paths. It must show: the 5 routes drawn, the CSP header exactly as written in ADR-0038, no console violation, no request to another origin, `localStorage`, `sessionStorage` and cookies unchanged after a token is entered and a call is sent, the call answered 200 with a token and 403 with a token that lacks the scope, and the instance's strict policy unchanged on every other page.
2. **ADR-0038 (the API reference with Scalar).** Supersedes Decision 4 of this plan: a new dependency, a CSP exception for one document, and a SvelteKit route in the shell outside the "UI routes go through the registry" rule (it answers a document of its own, not a page of a module). It records: why Scalar (the maintainer's decision), why self-hosted and pinned (the default CDN URL has no version), the options that must stay off (`persistAuth`, `proxyUrl`, `agent`, `mcp`, `telemetry`, default fonts), the exact CSP and why each directive is there, the Tailwind note above, what an upgrade of Scalar has to pass (the journey and the checks of item 9), and the alternatives rejected (Swagger UI, the existing renderer extended, an iframe, a CDN).
3. **Security schemes in the document.** `generateV1Document()` (`packages/contracts`) adds `components.securitySchemes` (`HTTPBearer`: `http`/`bearer`; `APIKeyHeader`: `apiKey` in the header `X-API-Key`) and `security` on every operation that is not public, and puts the scope the route needs into its description ("Needs the scope `registry.services.v1.read`"), from the route's `permission`. The spec route stays without `security`. This is additive, so it is still the first contract; the committed document and the runtime one stay equal (the existing test). Table-driven tests in `packages/contracts`.
4. **Dependencies and the asset.** `@scalar/sveltekit` as a dependency of `apps/web` (**amended in sprint 3: a development dependency**, because as a dependency the image's production install pulled `@sveltejs/kit`, Vite and TypeScript through the wrapper's peer dependency, +127 MB; measured in [ADR-0038](adr/0038-api-reference-with-scalar.md), decision 2), `@scalar/api-reference` as a **development dependency** (only its built file `dist/browser/standalone.js` is used; its 27 dependencies do not ship). Both pinned to an exact version. A small Vite plugin in `apps/web/vite.config.ts` emits the file as a hashed, immutable asset (nothing is committed; the package's `exports` do not offer the file, so the plugin resolves it by the package's directory). The pull request description says why each dependency is added, with the licences (MIT) and the sizes; the three images build and carry the asset (**10.9 MB** more on the `registry` image, measured in sprint 3, not the 4.5 MB first expected: the script with its two precompressed copies and the wrapper's code in the server bundle); Dependabot proposes upgrades and the journey is the gate.
5. **The reference route:** `apps/web/src/routes/docs/reference/+server.ts` (`GET` only), a thin handler: a nonce per request, `ScalarApiReference({ url: <the document of this instance>, cdn: <the asset>, nonce, pageTitle: <the instance name from the settings> })`, the headers of ADR-0038, `Cache-Control: no-cache`. The document's address and the asset's address are built with the helper the shell uses for the base path (never a hard-coded `/`), and the page title and the back link carry the instance name from `core.settings` (rule 9). Options: `withDefaultFonts: false`, `telemetry: false`, `agent: { disabled: true }`, `persistAuth: false`, `showDeveloperTools: 'never'`, no `proxyUrl`, no `mcp`, no `servers` (the document's own server is this origin plus the base path), the HTTP client `curl` first. Scalar's own texts are English: `@scalar/api-reference` 1.74.0 has no locale option (checked in its type declarations); the landing page is en and de.
6. **Theme.** Scalar's variables (`--scalar-*`) are set from the shell's two DaisyUI themes (`scorpion` and `scorpiondark`, `app.css`) through `customCss`, with the values in one place and a test that fails when they drift from `app.css`; contrast is checked by axe in both themes. The document follows the person's choice of the shell (`scorpion.theme`, or the system), set by a small inline script that carries the nonce; Scalar's own toggle is hidden so there is one switch. A slim bar above the reference names the instance and links back to `/docs` (our markup, the nonce on its style); the exact way (post-processing the response of the handler, or Scalar's own `customCss` and header) is settled in the prototype.
7. **The landing page `/docs`** (the existing public page of `core.ui-shell`, `ui/docs.ts`, `Docs.svelte`): the operations table is replaced by what a person needs before the reference: what v1 is, how to get a token in three steps (the profile page, a token with the scopes of the routes, `Authorization: Bearer` or `X-API-Key`), the scope of each route from the committed document (`x-permission`), the address of the document, a note that a browser application needs its origin in the allow-list of `public-api`, and a link to the reference (`data-sveltekit-reload`: the reference is a document of its own, so the router must do a full load). No API call on load beyond what the page makes today. en and de messages; `docs.test.ts`, the component test and `shell.spec.ts` (which expects the `/openapi.json` cell today) change with it.
8. **The spec diff in CI:** `pnpm openapi:diff` compares `apps/web/src/generated/openapi-v1.json` with the one of the **last release tag** (`git show v<last>:…`) and fails a breaking change (a removed path or method, a removed or renamed field, a narrowed type, a new required request field, a removed enum value, a removed security scheme); an additive change prints a summary into the job. `v0.9.0` carries a document with no paths: the job passes and says that this is the first contract. Decision 6 stands (a small script of our own, its gaps in the backlog).
9. **The journey (Playwright, both base paths) and the checks of the reference:**
   - A person signs in, makes a token with the right scope on the profile page, opens `/docs`, follows the link, pastes the token into Scalar's authentication and runs `GET /providers`: the legacy envelope appears. A token that lacks the scope gets 403 in the same panel. A plain request with the token returns the same envelope.
   - The CORS answer for an allowed and a disallowed origin (the sprint 1 behaviour, now through the documented flow).
   - **No request leaves the origin** from the landing page or the reference (`page.on('request')`); the token is in no `localStorage`, `sessionStorage` or cookie, and not in the request log or the audit trail (a test).
   - **CSP:** the reference carries exactly the policy of ADR-0038, and every other page of `security-headers.spec.ts` still has the strict one.
   - axe on the landing page and on the reference in both themes. If Scalar's own markup has violations the page cannot fix, the exclusions are named one by one with the reason and a link to the upstream issue, in the test; otherwise the page is axe-clean.
10. **Gate 2 evidence** ([implementation.md](implementation.md) Gate 2): the registry profile image builds and starts (the existing `Image (registry)` job), the v1 contract tests pass, and the journeys of M6 and M7 pass. The statement that the profile **runs on staging with real organisation and service data from a partial migration dry run** needs the tool of M13 and the maintainer's staging: it is the maintainer's check (Decision 7), not a task of this sprint.

## 10. Decisions taken

Answered by the maintainer on 2026-10-13.

1. **Permission of a v1 read:** one per route family (`registry.organisations.v1.read`, `registry.services.v1.read`), granted to the role `user` by default, so a token's scope names exactly what it reads and an administrator can withdraw the API without touching the screens.
2. **No anonymous v1 read.** v1 always needs a token; the anonymous reads are the M7 public records. **One exception, decided in sprint 1:** `GET /api/v1/openapi.json` (the description of the API, no record) is `public: true` with a reason; a walker fails any other public v1 route.
3. **v1 services carry the public flag and the Schema.org profile in M8:** the flag in the row, and `GET /api/v1/services/{id}/schema-org` in sprint 2 (the same builder and escaping as the internal route, never the contact point). The backlog line "A public read of `services` in v1" is closed by sprint 2.
4. **`/docs` extends the existing renderer** (a small try-it-out form); no Swagger UI, no new dependency, no CSP relaxation. **Superseded 2026-10-14 by Decision 9.**
5. **The change of the rate limits is not part of M8** (a separate pull request with V7 and V8 entries, between M8 and M9); M8 only proves per-token limits for v1. **Amended 2026-10-13 (sprint 1):** the prototype showed that two tokens behind one address share the address bucket, so the claim of §4 item 6 did not hold. The maintainer chose to change `pipeline/rate-limit.ts` in sprint 1 over wording the claim down: the address bucket of a token call is separate and ten times larger, nothing else about a limit changes ([ADR-0037](adr/0037-public-api.md), decision 1). The review of the limits against the calls per page stays a separate pull request.
6. **The spec diff is a small script of our own** (paths, methods, required request fields, response fields, enums), with its gaps recorded in the backlog; revisit when v1 grows in M9 to M11.
7. **The staging dry run of Gate 2 is the maintainer's** and does not block the release.
8. **The M8 release is `0.10.0`.**

Added 2026-10-14 (the maintainer, after sprint 2):

9. **The documentation is served with Scalar** (`@scalar/sveltekit`, <https://scalar.com/products/api-references/integrations/sveltekit>), as its own full-page document at `/docs/reference`, behind the landing page `/docs` that stays a shell page (themed, en and de) and links to it. Self-hosted and pinned, never from the CDN. The reference document, and only that document, may carry `style-src 'unsafe-inline'` (Scalar writes styles at run time; the prototype of 2026-10-14 measured 19 violations under the strict policy and none with this); scripts stay `'self'` plus a nonce, `connect-src` stays `'self'`, and every other page keeps the strict policy. The Tailwind heads-up (<https://scalar.com/products/api-references/themes#tailwind-css>) applies only if Scalar and Tailwind ever share a document; it is recorded in ADR-0038. Replaces Decision 4; the new dependency, the CSP exception and the route outside the registry are written down in ADR-0038.
10. **The spec carries its security schemes** (decided 2026-10-14, §6 item 3): `HTTPBearer` and `APIKeyHeader`, `security` on every non-public operation and the scope in each description, so that the reference can take a token. It is additive.
11. **The two Scalar dependencies are approved** (2026-10-14): `@scalar/sveltekit` (a dependency of `apps/web`; **built as a development dependency in sprint 3**, see §6 item 4 and ADR-0038, for the reason measured there; the maintainer can veto it in review) and `@scalar/api-reference` (a development dependency; only its built file ships), both pinned to exact versions. The pull request description of sprint 3 says why each is added.

## 11. Risks

| Risk                                                                    | Consequence                                           | Mitigation                                                                                                                                                                |
| ----------------------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The CORS step opens a cookie-authenticated route to another origin      | A CSRF-like exposure on `/api/internal`               | The step applies to `/api/v1` only, never sends `Allow-Credentials`, and a test proves `/api/internal` answers no CORS header                                             |
| The spec grows by accident (an internal route leaks into v1)            | A public contract nobody chose                        | v1 comes only from `r.public('v1')`; a test lists the v1 paths of the full profile and fails on an unexpected one                                                         |
| A row of v1 carries a field the internal read hides (the contact point) | A leak through the one surface that is easy to script | The v1 field tables, the walker, and a test that no v1 schema has the contact fields                                                                                      |
| The first spec becomes the contract before it is right                  | A breaking change needs v2                            | The diff job passes on the first release; sprint 2 pins the row shape in a table first, and the maintainer reviews it                                                     |
| Audit on every call grows the audit table fast on a busy token          | Retention and storage                                 | `apiRetentionDays` exists; sprint 1 measures the size per 1000 calls and writes it in the backlog                                                                         |
| M8 touches `pipeline/**`, so V7 and V8 go stale at the release          | `pnpm security:asvs --release` fails                  | The sprint's pull request updates the chapter files; the maintainer re-assesses before the release branch                                                                 |
| E2E time grows again with the journey and the axe checks                | A slower CI                                           | One journey for the token-to-call path; reuse the stack and the helpers of M7; no new project                                                                             |
| The reference relaxes the CSP (`style-src 'unsafe-inline'`)             | Injected CSS on the reference document                | Only that document; scripts stay `'self'` plus a nonce; no session data on it; the policy is pinned by an e2e test, and every other page is tested to keep the strict one |
| Scalar loads code or talks to a host we did not choose                  | A supply-chain or privacy leak on a public page       | Self-hosted pinned bundle, options off, `connect-src 'self'`, an e2e check that no request leaves the origin, Dependabot upgrades gated by the journey                    |
| A new Scalar version changes its markup, options or CSS needs           | The reference breaks or needs a wider policy          | Exact versions; an upgrade is a pull request that must pass the journey, the CSP test and axe; ADR-0038 says what to check                                                |
| The wrapper and the bundle drift apart (two packages)                   | A mismatch of options                                 | The versions are pinned together in one place and named in ADR-0038; the prototype test runs on the pair                                                                  |
| The try-it-out sends a token to a server the person edits in the UI     | A token reaches another host                          | `connect-src 'self'` makes the browser refuse it; the journey tests it; the page says the token is used for this instance only                                            |
