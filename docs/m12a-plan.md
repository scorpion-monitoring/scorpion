## 2. Scope

**Sprint 1: the eight fixes** (`feature/m12a-polish`)

1. **Drizzle studio.** `drizzle.config.ts` at the root (all module schemas, `DATABASE_URL`), `pnpm db:studio`. Dev only: bound to `127.0.0.1`, never in a profile or an image, documented in CONTRIBUTING with the warning that studio can write to the database. A drift test: the config lists every module that has a `db/schema.ts`.
2. **Hierarchical token permissions.** A tree built from the dotted ids (`registry` > `services` > `service` > `read`); a parent is a tri-state checkbox (checked, partly, unchecked) that selects or clears every leaf below it and says how many it covers; keyboard (arrows, space) and axe; the stored value stays the flat list of ids, so the API is unchanged. Tree-building and selection are pure and unit-tested.
3. **`/catalog/*`** (decisions A and B). The public pages become `/catalog/services/:slug` and `/catalog/organisations/:id`; the new landing page `/catalog/services` is a **public, searchable, paged list of published services** (name search, stage and consortium facets; a new public list route on the internal surface, rate-limited, never v1). The public records move with them (`GET /catalog/services/{ref}`, `/schema-org`, `/catalog/organisations/{id}`, `/catalog/kpi/rimo.ttl` and `.jsonld`). **No redirects from `/public/...`** (the pages were never shown to users). Schema.org `url`, `PUBLIC_PAGES`, the docs, the contract and e2e tests and the ASVS V8 note follow; a test keeps "an unpublished service is the same 404 at the new address". `/services` stays the signed-in catalogue. Public v1 stays unchanged (`pnpm openapi:diff`).
4. **Facets full width** now (layout only); the redesign is sprint 3.
5. **Sidebar: the most specific entry wins**, and the **sidebar shows the hierarchy**: an entry whose path lies below another entry's path is drawn indented under it (`Pending approvals` under `Users`, `Impact` under `Services`), so the order is no longer a flat list of lookalikes. The nesting is derived from the registered `ui.nav` paths (no new field), and a unit test runs over the navigation of the `full` profile: on every page exactly one entry is current. E2E for `/admin/users/pending` and `/services/evaluate`.
6. **Token copy dialog.** The created-token view has a very large token container; reproduce it in a browser first (probably an alignment or overflow rule), fix it, and check it at narrow and wide widths and with the long and the short token.
7. **Default logos and the footer.** The Scorpion mark ships as built-in light and dark assets of the web app (**supplied by the maintainer**; sanitised like any SVG) and is the fallback of the two logo slots until an operator uploads one. The footer keeps `© year instanceName` (the maintainer's decision of 2026-11-06, after the discussion of a separate holder setting) and **adds a fixed software attribution next to it**: "Powered by Scorpion" with the version and a link to the licence. No new setting. **CLAUDE.md rule 9 ("no hard-coded branding: product name ... from settings") gets an ADR and an amendment:** the attribution of the software is the software's own identity, not instance branding; instance name, sender, URLs, contact and legal texts stay settings. A test pins the footer (the instance name in the copyright, the attribution present and not editable).
8. **Icons from Tabler, at build time** (decision on icons). `@tabler/icons` is added as a **dev dependency only**; a script (`pnpm icons:generate`) copies the icons the app uses into `packages/contracts/src/icons.ts` (the table stays closed; MIT notice added to the licence file), and `pnpm check` fails if the generated file differs. **Sprint 3: the faceted search redesign** (`feature/m12a-facets`; brainstorm held 2026-11-16, decisions in §3)

The behaviour of today's faceted search is liked and stays: OR inside a facet, AND between facets; each facet counts over the set filtered by the search and all the _other_ facets (ticking a value never hides its siblings), counts are services, a selected value with no match stays with count 0, "No consortium" / "Unknown" are real values; the URL state `?q=&f.<facet>=<value>&sort=&dir=&page=&pageSize=` is shareable and a filter change returns to page 0. **The API and the URL format do not change.** The sprint changes the look and the flow, in one shared `ui-kit` component used by both catalogues (`modules/registry-services/ui/Catalogue.svelte` and `PublicCatalogue.svelte`).

_Problem._ The most frequent task on `/services` is **finding a known service to edit**, and today's page is built for browsing: the search is a separate form with a button (not live, unlike the filters), the uncapped facet lists (Provider, Licence, the KPI set of `kpi.framework`) set the height of the page, below `lg` a 360 px screen shows a column of checkboxes before the first service, nothing says how many services match after a change, and the selection is drawn twice (badge and checked box), copied in both catalogues.

_Goals._ (1) A known service is reached by typing part of its name, with no button and no scrolling, at 360, 768 and 1440 px. (2) A facet with 300 values takes no more room than one with 3. (3) Every change is announced (the match count in a live region) and the keyboard path, the axe results and the screen-reader output are proved by tests, not asserted. (4) The admin chooses the look, and every look keeps the same behaviour because they share one state model.

_Non-goals._ No change to the list API, the facet registry contract or the URL format (the brainstorm's constraint). No new runtime dependency (Guidepup is a dev dependency, item 7). No change to the table itself (columns, sort, paging stay; a direct "edit" action in the row goes to the backlog). No saved searches or per-user default filters (backlog). No VoiceOver on iOS in the automated gate (not automatable on hosted runners).

_Who._ A signed-in editor or admin looking for one service to edit (search first); a reviewer narrowing a set ("de.NBI, in production, CC licence"; facets first); an anonymous visitor browsing the public catalogue (two facets, browses rather than searches); a keyboard or screen-reader user in each of these roles.

**The three renderers.** The setting (item 6) chooses one of three looks, **all three permanent** (the maintainer's decision; the plan's earlier "remove the loser" is dropped):

- `sidebar`: today's look, unchanged apart from the shared count line and live region (item 1).
- `bar` (option B): a live search box, a row of facet buttons under it (`Consortium (2) ▾ Stage ▾ …`, the number is how many values are chosen) that open the facet's value panel as a popover (a bottom sheet below `sm`), and one row of chips under the bar with "Clear all".
- `combined` (option A, the primary): **one control** above the unchanged paginated table. Typed text filters the table by name live; chips for the chosen facets live inside the box; focusing the empty box opens the list of facets; a facet opens its value panel.

**Items**

1. **Shared state and feedback** (size M; `packages/ui-kit`). One state model behind all three renderers, built on `facets.ts` (`parseFacets`, `serializeFacets`, `toggleOption`, `setRange`, `clearFacet`): the selection, the text, the URL sync and the return to page 0 live once, and a renderer only draws. The search becomes **live** in every renderer (debounced, about 250 ms; typing never adds one history entry per keystroke: the history behaviour of a filter change stays what it is today). A **count line** ("12 services match", "1 service", "No services match" with a "Clear all"; when the typed text matches no service name but facet values, decision Q2: the table shows 0 rows and the line says "No services match the name" and links the best facet match, "Filter by Provider: IPK Gatersleben (12)", without changing what `q` means) sits above the table, and a polite live region says the same after each change, in English and German. The two catalogues lose their copied badge markup and their separate search form.
   - _Acceptance:_ a change in any renderer gives the same URL as today for the same selection (a table-driven unit test over `serializeFacets` and the existing e2e of `components/facets.spec.ts` stay green); the live region's text after each change is asserted in e2e; at 0 matches the selected values keep count 0 and stay removable.
2. **Value panels** (size M; `packages/ui-kit`). One panel per facet type, used by `bar` and `combined`: a **list panel** (checkboxes with counts; for more than 8 values a filter field on top, the first 50 values and "N more, type to narrow"; the filter matches the label in the page's language, accent-insensitive) and a **range panel** (from/to number inputs with the definition's `min`, `max`, `step`; Enter applies; the chip reads `Year: 2018–2022`, an open end `Year: ≥ 2018`). A facet type picks its panel through one map, so a future facet type adds a panel without an `if` in the renderers (CLAUDE.md rule 7, applied inside the kit).
   - _Acceptance:_ 2 values and 300 values (the harness scene of item 7) both render without a page scroll inside the panel's max height; the range panel refuses `min > max` with a message, not a request.
3. **Renderer `bar`** (size M; option B, the fallback). As described above. Facet buttons are disclosure buttons (`aria-expanded`, `aria-controls`); Escape closes the popover and returns focus to its button; the chip row's chips are buttons named "Remove Consortium: de.NBI, NFDI4Plants".
4. **Renderer `combined`** (size L; option A).
   - _Structure:_ an ARIA 1.2 combobox (`role="combobox"` on the input, `aria-expanded`, `aria-controls`, `aria-activedescendant`) with a listbox in two levels: the facet list ("Filter by"), then a facet's value panel (item 2) with a back entry. The chips sit before the input inside the same bordered box, are buttons outside the listbox, and are reached with Shift+Tab from the input (not with the arrow keys).
   - _One chip per facet:_ `Consortium: de.NBI, NFDI4Plants ×`; a long chip truncates to `Provider: IPK Gatersleben +2` with the full text in its accessible name. The × clears the facet; a click on the chip opens that facet's panel. The **list stays open while picking**, so OR within a facet is several Space presses. ✕ at the end of the box clears text and filters.
   - _Typing:_ free text filters the table by name at once; the dropdown meanwhile offers **matching facet values** with counts ("Provider: IPK Gatersleben (12)"). Enter on an offered value adds it as a chip and removes the typed text. The **`facet:value` shortcut ships now**: `provider:ipk` narrows the dropdown to that facet's matching values; the facet is matched by id or by its label in the page's language (`provider`, `Anbieter`), a value with spaces is quoted (`provider:"IPK Gatersleben"`), and an unknown facet name is plain search text, never an error.
   - _Keyboard path:_ Tab into the box → the facet list opens → ↓/↑ move, Enter or → opens a facet → typing narrows its values → Space toggles a value (list stays open) → Escape or ← goes back one level → Escape on the facet list closes it, focus stays in the input → Backspace in the empty input removes the last chip (announced) → Tab leaves for the table. Focus never leaves the input while the dropdown is open.
   - _Mobile:_ below `sm` the box shows two lines of chips at most and folds the rest into a `+N` chip that expands the box on activation; the dropdown is a full-width panel under the box (not a modal), so the count line stays in view.
   - _Public page option:_ `shortcuts` (on in `PublicCatalogue.svelte`, off in `Catalogue.svelte`) shows the facet names as small buttons under the box (`Consortium ▾ Stage ▾`) that open the dropdown at that facet, for visitors who do not think to click into a search field.
5. **Both catalogues use the component** (size S; `registry.services`). `Catalogue.svelte` and `PublicCatalogue.svelte` render the chosen renderer with the facets the API already returns (registry contributions such as the KPI set of `kpi.framework` included); the public page stays anonymous and shows only the public facets.
6. **The setting** (size S; `registry.services`, owner of the catalogues). `catalogueFilters` in `settings-schema.ts`: `sidebar` | `bar` | `combined`, with a title and a description for the generated settings screen, in the manifest and the module's README. **Default for a new instance:** `combined` once its gate (item 7) passes in this pull request; if it does not, the pull request ships with `sidebar` as the default and `combined` is not offered (never selectable while its gate is red). Applies to both catalogues. **Delivery (decision Q1):** both list answers of `registry.services` (the internal one of `/services` and the anonymous `GET /catalog/services`) gain an additive field `filterStyle` with the setting's value, so the setting stays in the module that owns the catalogues, a signed-in member who may not read the settings still gets it, and public v1 does not move; a contract test pins the field. **Existing instances keep `sidebar` (decision Q4):** the upgrade stores `sidebar` explicitly for an instance that already has services settings, so only a new instance starts with the schema default `combined`; the changeset tells operators the new looks exist.
7. **Tests and the screen-reader gate** (size M to L; `apps/web/e2e`, a new CI job).
   - Harness scenes in `apps/web/e2e/components/harness/scenes/`: 2 facets × 3 values, 6 facets, one facet with 300 values, one range facet, a 0-match state; each scene runs per renderer.
   - Playwright per renderer: ARIA snapshots (role, name, `aria-expanded`, selected state, `aria-activedescendant`) at every step of the keyboard path; focus after Escape, after removing a chip and after "Clear all"; the live region's text after each change; **axe on every state** (closed, facet list, value panel, range panel, overflowing chips at 360 px) in light and dark.
   - **Guidepup** (`@guidepup/playwright`, `@guidepup/setup`, dev dependencies; the PR says why): VoiceOver on a macOS runner and NVDA on a Windows runner, against the harness page with the API answered by Playwright route mocks (no Docker on those runners, so no server and no database). For each step of the `combined` keyboard path the spoken log must contain the key phrases (the combobox and its state, an option's name, count and checked state, "12 services match" from the live region); phrases, not whole strings, since the readers word them differently across versions. **Spike first** (the first two days, next to item 1): if VoiceOver on hosted runners is unstable, **NVDA alone is the required check** and VoiceOver runs nightly for information only (decision Q3); the sprint's "Found differently" block records which it was.
   - The job runs when a pull request touches the facet component or its scenes (path filter), nightly on `dev`, and is required on `release/*`. Workflow rules (CLAUDE.md, Scorecard): actions pinned by full SHA, `permissions: contents: read` at the top, no `pull_request_target`.
   - **j08** (`journeys/j08-find-services.spec.ts`) and `accessibility-services.spec.ts` run under both base paths for each renderer (the setting switched by the test); their assertions are updated to the new markup, **not weakened** (every step of today's journey: two facets whose counts follow the filtered set, the page reset, removing one value, sort, 20 per page; the service with two consortia and the one with none).
8. **Docs** (size S). The README of `registry.services` (the setting) and of the kit's component, `docs/ui-style-guide.md` (the three looks and when to choose which), the docs export, a changeset (`minor`: operators see a new setting and a new default look). No ADR is expected (no architectural change); the field `filterStyle` is additive on internal answers and needs none.

**Sprint 4: admin-editable theme colours** (`feature/m12a-theme-colours`; added 2026-11-06, decision: **full control**, not only a primary and an accent colour)

An administrator changes the colours of both themes (light and dark) in the Branding screen of the admin area. Size: about one sprint (the estimate given was 2 to 3 days for the full set).

1. **Settings.** A `colors` group in the branding settings of `core.settings`, one value per daisyUI colour token for each of the two themes (`primary`, `secondary`, `accent`, `neutral`, `base-100`, `base-200`, `base-300`, `info`, `success`, `warning`, `error`, and the `*-content` pairs), each optional; an unset token keeps the built-in value. The values are `#rrggbb` only, never free CSS. The screen is generated from the schema like the rest of the branding screen; a "reset to default" per theme and a preview of the two themes.
2. **Delivery under the CSP.** The policy allows no inline style, so the overrides are a **stylesheet route** (for example `GET /theme.css` on the web app, built from the branding read) linked from the layout, with a version in its address so a change is seen at once and a short cache. It writes only the variables of the known tokens, with values that passed validation, nothing else. The built-in themes stay in `app.css`; the route only overrides.
3. **Contrast.** A pure function checks every text/background pair of the tokens (content on its colour, base-content on the three base colours) against WCAG AA (4.5:1; 3:1 for large text and borders) for each theme; a failing set is refused on save with the pair named, and the content colours may be left to be derived (the best of black and white). Table-driven unit tests, a rollback test (nothing is half-saved), a denied-permission test.
4. **Everything that draws colour follows the tokens.** The charts (palette), the badges, the sparkline and the logos' theme switch read the variables, not fixed colours; a test fails for a hard-coded colour in `modules/**/ui` and `packages/ui-kit` outside the palette definition. The e2e suite runs axe in both themes with a custom set applied, under both base paths.
5. **Docs.** README of `core.settings` and `core.ui-shell`, an ADR for the stylesheet route (a decision about the CSP and the cache), the docs export, and an ASVS note if a scoped path changes. The documentation screenshots keep the default colours (the custom set is applied only inside the tests).

**Sprint 5: the blocking items of the triage** (`feature/m12a-blocking`; added 2026-11-16; **runs before sprints 3 and 4**, the maintainer's order)

The eight lines of `docs/backlog-triage.md` that break something, with the decisions of 2026-11-16. Each is a fix of a defect the code shows today; none adds a module, a public v1 change (v1 stays additive) or a runtime dependency. Size: M to L, **one pull request** (CLAUDE.md: batch), with the items below as separate commits. Every service change gets the integration tests CLAUDE.md asks for (a denied-permission case, a rollback case for a multi-row write); calculations get table-driven unit tests; the e2e specs run under both base paths.

1. **Rate limit keyed by session** (triage lines "Too many 429s when administering", "The loader makes nine reads" and "A bucket of its own for the dashboard"; size M; `apps/server/src/pipeline/**` and `packages/contracts/src/route.ts` are ASVS-scoped). A signed-in caller's `default` bucket is keyed by the session (a hash of the session id, never the cookie), with the address bucket kept as a ceiling with headroom (like `TOKEN_ADDRESS_FACTOR`), so two people behind one address stop sharing 120 a minute and a person's own navigation no longer drains the address. Anonymous callers and the `strict` group are unchanged. Then the loader of the data-submission page reads the reference data (adapters, the two vocabularies, the value types) **once per visit** instead of on every month change (5 of its 9 reads). Tests: the bucket keys (a table: anonymous, cookie, token, two sessions on one address), a contract test that `429` still carries `Retry-After`, and the measurement of the old spec re-run (seven month changes in a row no longer exhaust the burst). ASVS: update the matching `docs/security/asvs/v*.yaml` (the chapter `tools/asvs-report/scope.ts` maps `pipeline/**` to) with tagged tests as evidence; the human fields stay the maintainer's.
2. **A member's write token** (triage line "A non-admin member cannot make a working write token"; size S to M; `core.authz`, `core.identity`). The choice between the two options in the backlog is the first task, recorded as a short amendment of ADR-0015: either the token form lists the scoped permissions a person may hold on some resource, or the service accepts `submit` for the owner of a token that names `kpi.ingestion.v1.write` (the owner still has to be allowed). The recommendation is the second: it keeps `GET /account/permissions` a statement about roles, and the check stays where the write is made. Tests: a member with the provider policy makes a working token and writes a month; a member without it gets a 403 at the write (the denied case); an admin is unchanged. An ASVS note if `core.authz` changes.
3. **The reminder on or after its day** (size S; `kpi.ingestion`). - **`combined`, as built** (item 4). Four points the spec did not settle, decided by what the tests and the gate showed:
  - **No active option on focus**, and on going back the facet just left becomes active: with an active option on focus NVDA read the option and never the combobox; with none after Escape it read only the box. The gate's spoken log now has "Search services, combo box, expanded" and "Consortium, 1 chosen" at those steps.
  - **Chips out of the tab order**: the chips sit before the input, so Tab into the box would have reached a chip first. They are `tabindex=-1`; Shift+Tab from the input reaches the last chip and Tab and Shift+Tab move between them (the spec's "reached with Shift+Tab").
  - **One listbox for the first level**: with a name typed, the list offers matching values (group "Matching values") **above** the facets ("Filter by"), so a facet opens without giving up the search. While a name is typed the list shows only when it has values to offer or is asked for (↓, a click), and it is drawn **in the flow** under the box (as the sketch has it) rather than over the table: drawn over the table, it covered the rows the name had found (a spec clicked an offer instead of its service), which is goal 1 of the sprint. A press outside closes it **after** its click, so a click is not moved by the page closing under it.
  - **The fold below `sm`** keeps one chip and `+N`: with two chips the box took three lines at 360 px. A `facet:value` text is never sent as a search; Escape puts back the search it stood in for.
