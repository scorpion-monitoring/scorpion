## 2. Cross-sprint rules

- **One pull request per sprint** (CLAUDE.md). ADRs, READMEs, backlog lines, the regenerated OpenAPI document and review fixes go into the sprint's pull request; push when the sprint is complete and verified (`pnpm check`, the tests of every package touched, `pnpm test:contract`, the e2e of any journey changed, `pnpm openapi:diff`). The release (sprint 4) follows CONTRIBUTING.md "Releases"; every outward step waits for the maintainer.
- **One new module, additive reads elsewhere.** `kpi.impact` depends on `core.authz`, `core.settings`, `registry.services`, `registry.organisations`, `kpi.framework`, `kpi.ingestion` and `kpi.analytics`; `core.ui-shell` is an **optional peer** (as for `kpi.analytics`). It reads other modules only through their `public.ts`, never their tables. Nothing depends on it. The additive reads are listed in §3.
- **Everything the page shows is computed from data**: the stages and their labels from the vocabulary `stage`, the aggregate functions from the registry `analytics.aggregate`, the headline from the evaluation. No `if (stage === 'DEV')`, no list of stage keys, no pg enum (CLAUDE.md rule 8; `no-pg-enum.test.ts` guards it).
- **A gap is a gap.** A month without a value is `null` (shown "no value"), never zero; a yearly aggregate is over the months that have a value and says how many (`n of 12`), so a sum of nine months is not read as a year. A headline of a text value type is "not numeric", never parsed (decision 11 of M11).
- **Row states are explicit and exclusive** (FEATURES §3.9): `ok`, `no-data` (the service has the evaluation and no value in the year), `no-evaluation` (its KPI set has no headline, or it has no KPI set), and `error` (the headline cannot be read, e.g. the indicator left the set or the value type does not allow the aggregate any more); each says what to do in words; none is a blank cell. An `error` of one row never fails the page.
- **Permission:** a plain `kpi.impact.read`, held by the role `reviewer` and by Admin (not by `user`), checked in the route and again in the service. It is plain, not scoped: a Reviewer evaluates every consortium (FEATURES §3.9: "Reviewer or Admin"). The routes name no person, no run and no file name in an answer.
- **Calls are counted.** The page's server `load` reads the consortium list; choosing a consortium and a year makes **two** reads (tiles, table) and no more; changing the year makes **one** (the table); the e2e spec counts them and writes `[impact-calls]` lines into the report, as M11 did.
- **The read model is never the only source of the tiles.** Counts of services (total, open source, per stage) are queried live on every request (they are cheap and must follow a stage change at once); only the monthly and yearly figures are stored (§3).
- **Public v1 is unchanged** (`pnpm openapi:diff`). New routes are internal, in the legacy list envelope where they list, with a stable order (name without case, then id).
- Every pull request carries a changeset (package `scorpion`); sprints 1 to 4 are `minor` where an operator or a person can see something, `patch` otherwise. Update each module README with every manifest change.

## 3. The model

**Tables.** The architecture lists none ("read model"), and the read model needs somewhere to live. **Proposed (decision 15): plain tables written by a service function in one transaction, not SQL views** (CLAUDE.md "No correctness-critical SQL views"; a materialised view can only be refreshed whole, and one measurement of one service must not recompute every consortium). ADR-0048 records the deviation from the architecture's wording. Prefix `kpi_impact_`:

| Table                | Holds                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kpi_impact_year`    | One row per (service, calendar year): the state (`ok`, `no-data`, `no-evaluation`, `error`), the headline `indicator_id` and `aggregate` id as they were when computed, twelve nullable numeric month columns (`m01` to `m12`, value as stored), the yearly aggregate (nullable), `months_with_value`, `computed_at`. Primary key (service, year); no foreign key into another module's table |
| `kpi_impact_refresh` | The refresh bookkeeping (a row per run: what triggered it, how many rows it wrote, how long it took, an error text without a value), for the page that says "figures as of ..." and for tests                                                                                                                                                                                                 |

A foreign key may point only to core tables or declared dependencies (CLAUDE.md rule 3), so `service_id` and `indicator_id` are plain `uuid` columns checked by the service, as `kpi.ingestion` does for its references.

**What is live and what is stored.**

- **Tiles (live).** For a consortium: the number of its services (`total`), the number that are **open source** (licence is an OSI-approved, not deprecated, SPDX id: the `osiApproved` and `deprecated` flags of the cached list with the bundled fallback; a deprecated id is counted under "deprecated licence" and an id the list does not know under "licence unknown", neither as open source; decision 19), and **the number per stage for every term of the vocabulary `stage`**, active or deactivated, plus a line `other` for a stage key the vocabulary does not list. By default only **published** services are counted (decision 16); with `includeUnpublished=true` every linked service is. Every service of the consortium is counted **once**, however many consortia it has (defect 2's lesson; a service with no consortium link is in no consortium's count, as the legacy view dropped it, which is correct here).
- **Table (stored).** The per-service monthly and yearly figures come from `kpi_impact_year` rows, joined at read time with the live service list of the consortium (a new service shows `no-data` or `no-evaluation` at once, before any refresh, never a missing row). A service whose row is missing or older than its inputs is computed in the request and written (a read repairs, never fails).

**The refresh.** `refreshService(serviceId, years?)` recomputes the rows of one service in one transaction: it reads the service's KPI set and its evaluation through the new trusted read, the values of the headline for the year through `seriesAsSystem`, applies the aggregate from the registry (`analytics.aggregate`) and writes the row. It is triggered by:

- `measurement.recorded@1`: the years of `periods` (at most two years per batch of 120 months; a batch of more years recomputes each);
- `registry.service.updated@1` / `created@1` and `kpiSet.changed` of the service's set (the architecture's name; the event's real name and payload are re-checked on the first day), when the evaluation or the set's rows changed: all years of the service present in the table, plus the current year;
- a job `kpi.impact.system.nightly` (`0 3 * * *`) that recomputes **the current and the previous year of every service** and deletes rows of services that no longer exist: the repair for a missed event, so that no state depends on the event alone.

The job and the handlers are idempotent (a row is replaced, not appended) and bounded (at most 200 services a run slice, then the job queues the next slice).

**The yearly aggregate.** The aggregate id of the evaluation is a key of the vocabulary `aggregate`; the function comes from the registry `analytics.aggregate`, **never from a switch on its name**. The aggregate is over the months of the year that have a numeric value; a window with none is `no-data`. `avg` of a year of two values is the average of the two and says "2 of 12 months". The twelve columns hold the **stored values** (numbers), not formatted strings; the page formats with the value type of the headline indicator (unit, decimals) through `kpi.framework`'s value-type API, as the M11 widgets do.

**The additive reads on other modules** (each the sibling of a read that exists; each with its README line and a test in the owning module):

| Module                   | Read                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `registry.services`      | `listImpactRowsAsSystem(consortiumId)`: `{ id, name, slug, stage, license, published }` for **every** service linked to the consortium by the role `consortium` (the caller filters on `published`; the switch of decision 16 decides), once each, by name without case then id (at most 2,000; a larger consortium is a 422 on the page, never a silent cut). Trusted, no permission, no route |
| `registry.organisations` | `listConsortiaAsSystem()`: `{ id, name, abbreviation }` of the organisations of the consortium type, by name then id (at most 500). The page's picker lists only these                                                                                                                                                                                                                          |
| `kpi.framework`          | `evaluationOfServiceAsSystem(serviceId)`: `{ setId, indicatorId, aggregate, valueType, unit } \| null` (the evaluation of the set the service has now), and `servicesOfSetAsSystem(setId)` (for the refresh after an evaluation change; at most 5,000)                                                                                                                                          |
| `kpi.ingestion`          | none: `seriesAsSystem` is enough (one indicator, twelve months)                                                                                                                                                                                                                                                                                                                                 |
| `kpi.analytics`          | the aggregate lookup (`aggregateFor(id)`) through `public.ts`, if the registry is not reachable another way; otherwise none                                                                                                                                                                                                                                                                     |

**The routes** (internal; permission `kpi.impact.read` on each, the default rate bucket, `Cache-Control: no-store`; every one calls one service method which checks the permission again):

- `GET /kpi/impact/consortia`: the consortia the picker offers.
- `GET /kpi/impact/summary?consortium=&includeUnpublished=`: the tiles (`total`, `openSource`, `licenceUnknown`, `licenceDeprecated`, `stages: [{ key, label, active, count }]`, `otherStages`) and the time the licence list was fetched (`licencesAsOf`, `bundled`).
- `GET /kpi/impact/table?consortium=&year=&includeUnpublished=`: the table: one row per service (`serviceId`, `name`, `slug`, `state`, `headline: { indicatorId, name, unit, aggregate, label } | null`, `months: [12 × number | null]`, `yearly`, `monthsWithValue`), the years offered (the current year and the nine before it), and `figuresAsOf` (the oldest `computed_at` of the rows shown). An unknown consortium (not an id, or not a consortium) is a 422 naming `consortium`; a year outside the ten offered is a 422 naming `year`; a consortium with no services is an empty list, not an error. A page is a page of services (default 50, at most 200).

## 6. Sprint 2: the yearly table, computed live

**Branch:** `feature/m12-impact-table`. **Goal:** the per-service table of a year is correct, with its states, from the evaluation and the measurements, before any stored model exists. The numbers are the reference the model of sprint 3 must reproduce.

Work items

1. **The additive reads** of `kpi.framework` (`evaluationOfServiceAsSystem`, `servicesOfSetAsSystem`), with README lines and tests (a service with no set, a set with no evaluation, an evaluation whose indicator was removed from the set).
2. **The yearly calculation** (`service/year.ts`, pure): twelve months of nullable numbers and an aggregate function give `{ yearly, monthsWithValue }`; the function comes from the registry by id; table-driven tests for every aggregate (empty, one value, a gap in the middle, a negative value, a leap-year February month end, a year with all twelve) and **`fast-check` properties** (the result of `avg` lies between `min` and `max`; `sum` of a series with gaps equals `sum` of the series with the gaps removed; no function throws or returns `NaN`; the months are never reordered). It uses the library of `kpi.analytics`, not its own arithmetic.
3. **The row computation** (`service/rows.ts`): for one service and a year: the evaluation, the headline indicator's value type (a text headline is `error`/"not numeric"), the twelve month-end periods of the year, the values through `seriesAsSystem` (**one read per service**, one indicator, twelve months), the state by the rules of §2. A KPI the service has since dropped but still has values for is read (the series read does not look at the set); a headline the set no longer holds is `error` saying so.
4. **The route** `GET /kpi/impact/table` with the paging, the years offered, the 422s of §3, and a stable order. **The cost is measured here**: the table of a consortium of 50, 200 and 1,000 services over a year, the number of queries per request (it must not be one per month; one series read per service is the budget, and a batched read is the decision of this sprint if 1,000 services exceed 500 ms), written into the backlog and ADR-0048. This measurement decides whether sprint 3 is a speed-up or a correctness feature (§9, the second risk).
5. **Tests:** the states one by one on real Postgres (`ok`; `no-data`; `no-evaluation` for a service with no set and for a set with no headline; `error` for a removed headline indicator and for a text headline), a service whose KPI set changed during the year (the **current** evaluation is used for the whole year, stated in the README), the year boundary (a value on 31 December and one on 1 January), the order, the paging, 422 per bad parameter, a denied case per caller class, the same service in two consortia, a consortium of zero services.
6. **Documents:** README, `authorization.md` (the field table of the table answer: names, units and values of services a Reviewer may read, no person), the backlog, the changeset.

ASVS impact (sprint 2): **V8** (the table route needs the permission twice; the answer holds no person: tagged tests); V6, V7 and V10 `asvs-no-impact`.

Definition of done: as sprint 1.

## 7. Sprint 3: the read model, the refresh and the nightly repair

**Branch:** `feature/m12-impact-model`. **Goal:** the table is served from stored rows that follow every input within the transaction's reach, and a missed event is repaired by the night.

Work items

1. **The migration** for `kpi_impact_year` and `kpi_impact_refresh` (`pnpm db:generate --filter @scorpion/kpi-impact`; the prefix is declared in the manifest, the loader checks it after migrating); the schema file in `db/schema.ts`; a migration test (applies from nothing and from the previous migration).
2. **`refreshService`** (`service/refresh.ts`), one transaction per service, replacing its rows; it calls the code of sprint 2 (the model stores **what the live computation returns**, so there is one implementation, tested by comparing both for generated data: the property "the stored table equals the live table" over random services, evaluations and measurements).
3. **The handlers:** `measurement.recorded@1`, the service events, the set and evaluation change event; each queues the refresh through the outbox in the same transaction as the event (CLAUDE.md rule 6) and coalesces repeated triggers for one service (a batch of 120 months is one refresh).
4. **The nightly job** `kpi.impact.system.nightly` (`0 3 * * *`): the current and the previous year of every service, in slices of 200, rows of vanished services deleted, a `kpi_impact_refresh` row per run; a setting `refresh.enabled` (default on) and `refresh.yearsBack` (default 1, at most 9) through the module's settings schema.
5. **Serving from the model:** the table route reads `kpi_impact_year` joined with the live service list; a missing or out-of-date row is computed and written by the request (the page never shows an old figure with no sign): `figuresAsOf` says how old the oldest shown row is. The nightly figures of a past year are left alone unless an input event arrives.
6. **Tests (the heart of the sprint):** after `upsertBatch` of a month the table changes without a request-side recompute having to happen (the event ran); after a change of the evaluation's headline the rows of every service of the set change; a missed event (the handler is disabled in the test) is repaired by the nightly job and not before; a **rollback case** (a refresh that fails midway leaves the previous rows intact); two refreshes of one service at once leave one consistent row; a service deleted leaves no row after the night; the job is idempotent and bounded; the equality property of item 2; a denied case for the job's own status read, if the page offers one.
7. **Measure:** the refresh of one service, of a consortium of 200 services (the batch after an import) and the nightly run at 1,000 services, written into the backlog and ADR-0048; the table at 1,000 services from the model against sprint 2's live figure.
8. **Documents:** README (tables, handlers, the job, the settings, what `figuresAsOf` means), `authorization.md` (the stored table: no person, no run; the model is never writable through a route), ADR-0048's amendment, the backlog, the changeset (`minor`: a job and two settings).

ASVS impact (sprint 3): V8 unchanged in substance (no new route) unless the job page lists the new job; V6, V7 and V10 `asvs-no-impact`.

Definition of done: as sprint 1, plus the full `pnpm test` includes the migration test and the image module-set check includes `kpi-impact` in `full` only.

## 12. Decisions

Answered by the maintainer on 2026-10-22 (the recommendation was taken for 15, 17, 18, 20 and 21; 16 and 19 were changed). Each stays reversible without a migration until sprint 3 writes the tables.

15. **The read model is plain tables, not materialised views** (answered: as recommended). A materialised view is refreshed whole; one measurement should recompute one service. A table written by a tested service function is the finer-grained form of CLAUDE.md's "refreshed read model". ADR-0048 records the deviation from the architecture's wording. Sprint 2's measurement is still recorded, and if it shows the live table is trivially fast the maintainer may drop the model then.
16. **The impact page counts only published services by default and has a switch to include the unpublished ones** (answered, changed from the proposal). Both routes take `includeUnpublished` (default `false`); the page shows the switch to people who hold `kpi.impact.read` (Reviewers and Admin, who already read every service), and says which set the figures are for ("published services" or "all services"). The stored rows of the model are per service and independent of publication; the switch only changes which services are joined and counted, so the model does not double. Tests: the same consortium with a published and an unpublished service, both settings, the tiles and the table agreeing, and the count of a service that is published and unpublished again.
17. **The current evaluation applies to every year shown** (answered: as recommended), as the legacy page did; the page says "with today's headline". A history of evaluations is the backlog.
18. **A yearly aggregate is over the months that have a value, and says how many** (answered: as recommended): `sum` of nine months is shown with "9 of 12 months", `avg` of the months present; nothing is imputed.
19. **Open source means the licence is an OSI-approved, not deprecated, id of the cached SPDX list** (answered, changed from the proposal, which kept a deprecated OSI id): a deprecated id and a licence the list does not know are both **not** open source; the second is counted as "licence unknown" and the first is counted under its own line "deprecated licence" so that the tiles still add up. The page says what the two lines mean. Tests: an OSI-approved id, a deprecated OSI id, a non-OSI id, an unknown id, no licence.
20. **The permission is `kpi.impact.read`, plain, held by `reviewer` and Admin; there is no `user` access and no scoped variant** (answered: as recommended, FEATURES §3.9). An instance can add the permission to another role through the roles page.
21. **Four sprints** (answered: as recommended): tiles, live table, model, page and release; the release is folded into sprint 4 as in M9 and M10.
