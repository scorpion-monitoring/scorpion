# @scorpion/integrations

Adapters for external services (SPDX licence list, DOI content negotiation, OpenAlex), each with a timeout, retry, a Postgres cache and a test stub.

**Filled in:** M4b (`pwned-passwords`), M7 (`spdx`) and M16 (DOI, OpenAlex).

## `pwned-passwords` (M4b)

The Have I Been Pwned range API, for the password check of `core.identity` (ASVS 6.2.4, 6.2.12).

- `createPwnedPasswords(options)` sends only the first 5 hex characters of the password's SHA-1 (`GET /range/<prefix>`, `Add-Padding: true`); the password and the rest of the hash never leave the process. It times out after 2 seconds and keeps up to 1000 ranges in memory for 24 hours. No dependency: it uses Node's `fetch`.
- `check(password)` answers `breached`, `clean` or `unavailable`. `unavailable` (timeout, network, status) is counted in `pwnedPasswordFailures()`, which the server exposes as `scorpion_password_breach_check_failures_total`. The adapter does not decide what to do about it: `core.identity` accepts the password and logs a warning ([ADR-0026](../../docs/adr/0026-credential-rules-throttling-and-mail-confirmed-linking.md)).
- `createStubPwnedPasswords({ breached, unavailable })` never touches the network, for tests and for `NODE_ENV=test`.

## `spdx` (M7)

The SPDX license list, for the licence field of a service in `registry.services`.

- `createSpdx({ cache, fetch, now, … })` reads `licenses.json` of `spdx/license-list-data` with a 5 second timeout and three attempts (waits of 200 and 400 ms), keeps the list in memory and in the **cache port** for 24 hours, and shares one fetch between concurrent callers. The caller supplies the port (`registry.services` stores the list in `svc_license_cache`); without one the list lives in memory only. A cache that throws never fails a lookup.
- When the network and the cache both fail, the adapter uses the newest of the stale cached list and the **bundled copy** (`src/spdx-bundled.generated.ts`), and asks the network again after a minute. The bundle is generated by `node packages/integrations/scripts/generate-spdx.ts` from the release named in `src/spdx-pin.ts`; a test fails while the bundle is older than the pin, so bumping the pin forces a regeneration.
- `search(query, { limit })` returns `{ id, name, osiApproved, deprecated }`: exact id, id prefix, id, then name matches, current licences before deprecated ones, at most 100. `find(id)` and `has(id)` ignore case and answer for current **and deprecated** ids (a deprecated licence is accepted and marked, never refused).
- `createStubSpdx({ licenses })` answers from the given list, by default the bundled one, and never touches the network; `registry.services` uses it when `NODE_ENV=test`.
